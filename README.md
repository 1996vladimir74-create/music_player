# music_player — MicroPython

Полностью Python-прошивка для холодильного мини-проигрывателя с физическими виниловыми дисками/NFC.

## Зафиксированное правило проекта

**1 физический диск = 1 NTAG215 UID = 1 цифровой альбом = 1 папка на microSD.**

- RC522 читает UID NTAG215.
- ESP8266 сохраняет соответствие UID → папка в `tagmap.json` во внутренней файловой системе MicroPython.
- Первый неизвестный тег получает папку `01`, следующий `02` и т.д.
- После сохранения один и тот же UID всегда открывает ту же папку.
- `Previous` и `Next` работают только через `current_folder + current_track`.
- Команды глобального `next()`/`previous()` DFPlayer для переключения альбомов не используются.
- EC11: вращение = громкость 0–30, нажатие = Play/Pause.
- При устойчивом отсутствии NFC-тега останавливаются музыка, мотор и WS2812.
- Пока диска нет, **всё выключено**: кольцо не светится, мотор стоит. Индикация ошибок показывается только когда диск стоит на RC522:
  - диск не соответствует альбомам (нет такой папки на SD, либо таблица тегов заполнена) → кольцо **мигает красным**, звука и вращения нет;
  - нет SD-карты → кольцо **горит синим** (постоянно), мотор не вращается, звука нет.
- Громкость энкодером меняется на один шаг за один щелчок и работает также без диска.
- Режимы после сброса (кнопку держать при нажатии RST и ещё около 2 секунд):
  - ничего не нажато → проигрыватель;
  - **PREVIOUS** → USB-сервисный режим (REPL остаётся на USB, плеер не запускается);
  - **NEXT** → режим обновления по WiFi (см. ниже).
- WiFi во время работы плеера **выключен**.
- Hall sensor не используется.

## Язык и платформа

- **Язык:** Python / MicroPython.
- **Плата:** NodeMCU V3 LoLin ESP8266.
- **Среда выполнения:** MicroPython ESP8266.
- Никаких Arduino `.ino`, C/C++ библиотек и установки внешних Python-пакетов на плату не требуется.
- В репозитории находятся собственные минимальные драйверы `mfrc522.py` и `dfplayer.py`.
- `neopixel` берётся из стандартной поставки MicroPython.

## Финальная распайка

| Функция | NodeMCU | GPIO |
|---|---:|---:|
| RC522 SCK | D5 | GPIO14 |
| RC522 MISO | D6 | GPIO12 |
| RC522 MOSI | D7 | GPIO13 |
| RC522 SDA/SS | D8 | GPIO15 |
| RC522 RST | 3.3V | — |
| DFPlayer RX | TX | GPIO1 через 1 kΩ |
| DFPlayer TX | RX | GPIO3 |
| EC11 A | D1 | GPIO5 |
| EC11 B | D2 | GPIO4 |
| EC11 SW button | D3 | GPIO0, second button contact to GND |
| Motor control | D0 | GPIO16 |
| WS2812 DATA | D4 | GPIO2 |
| Previous/Next | A0 | ADC0 |

DFPlayer использует UART0 полностью: GPIO1/TX → DFPlayer RX и GPIO3/RX ← DFPlayer TX. Поэтому REPL UART0 отключается программой после старта.

WS2812 DATA перенесён на D4/GPIO2. GPIO2 является boot strap pin и должен оставаться HIGH во время запуска; вход DATA кольца не должен быть притянут к GND.

## SD-карта

FAT32:

```text
SD/
├── 01/
│   ├── 001.mp3
│   ├── 002.mp3
│   ├── 003.mp3
│   └── ...
├── 02/
│   ├── 001.mp3
│   ├── 002.mp3
│   └── ...
└── 03/
    ├── 001.mp3
    ├── 002.mp3
    └── ...
```

DFPlayer использует `playFolder(folder, file)`. Для определения числа треков активного альбома прошивка использует команду `0x4E`. Если ответ 0 — папки нет или она пуста (красное мигание). Если клон вообще не отвечает, применяется резервный лимит 15 треков, а реальный конец папки определяется по сообщению об ошибке «файл не найден» (кадр `0x40`, коды 5 и 6 — проверить на вашем клоне).

## Логика работы

```text
NTAG215 на диске
      ↓
RC522 → UID
      ↓
UID → tagmap.json
      ↓
folder 01/02/03...
      ↓
track = 001
      ↓
DFPlayer
      ├── Previous → предыдущий трек этой папки
      ├── Next     → следующий трек этой папки
      └── конец трека → следующий трек этой папки
```

При замене диска старый альбом останавливается, новый UID становится активным, выбирается его папка и начинается первый трек.

Новый (неизвестный) диск регистрируется в `tagmap.json` **только если** на SD есть следующая по порядку папка с файлами. Иначе слот не расходуется, кольцо мигает красным.

## Обновление по WiFi

Обновляются `.py`-файлы проекта. Саму прошивку MicroPython (интерпретатор) этот способ не заменяет, она по-прежнему ставится по USB.

Как это устроено: в режиме обновления плата подключается к вашему WiFi и запускает встроенный в MicroPython ESP8266 WebREPL — доступ по сети с паролем и передачей файлов. По документации MicroPython, WebREPL — экспериментальная функция, а передача файлов в ней «ещё более экспериментальная»; USB-загрузка остаётся запасным путём.

**Один раз по USB** (создать `wifi.json` на плате):

```text
python deploy.py COM3 --wifi
```

Скрипт спросит имя сети, пароль, пароль WebREPL (4–9 символов; ограничение стандартной `webrepl_setup`, по памяти) и, при желании, фиксированный IP. Образец формата — `wifi.json.example`. Необязательный `ap_password` (не короче 8 символов) включает резервную точку доступа `MusicPlayer` (адрес 192.168.4.1), если домашняя сеть недоступна.

**Каждое обновление:**

1. Положить рядом со скриптами `webrepl_cli.py` из <https://github.com/micropython/webrepl>.
2. Удерживая NEXT, нажать и отпустить RST, держать ещё около 2 с. Кольцо: синее «дыхание» — подключение, зелёное «дыхание» — готово, красное мигание — ошибка (нет `wifi.json`, неверный пароль WebREPL, нет сети).
3. На ПК: `python deploy_wifi.py 192.168.1.50` (IP — из `wifi.json` или из списка клиентов роутера; при ошибках он печатается в REPL по USB).
4. Скрипт загружает файлы и затем файл `reboot.flag`; плата видит его и сама перезагружается в плеер.

Режим сам выключается через 15 минут (`WIFI_MODE_TIMEOUT_MS`).

**Если новая версия сломана.** Если `player.py` не стартует (например, ошибка в загруженном файле), загрузчик пишет причину в `error.log`, возвращает USB-REPL и сам входит в режим обновления по WiFi, чтобы можно было залить исправление. Без `wifi.json` остаётся USB (PREVIOUS при сбросе).

**Безопасность.** Доступ защищён паролем WebREPL, но канал не шифрован, поэтому режим предназначен для домашней сети. Пароли хранятся на плате в `wifi.json` и `webrepl_cfg.py` в открытом виде (так же, как у стандартной настройки WebREPL). Не заливайте их в публичный репозиторий. Загрузка файлов не атомарна: при обрыве питания посреди передачи повторите её или используйте USB.

## Логи на NodeMCU

REPL при работе отключён, поэтому ошибки пишутся в файлы (файл удаляется, когда превышает `LOG_MAX_BYTES`):

- `error.log` — трассировки исключений основного цикла;
- `df.log` — сырые кадры от DFPlayer (включено `DF_DEBUG = True`; после первой настройки поставить `False`).

Читать файлы: сервисный режим (удерживать PREVIOUS при сбросе), затем `mpremote connect COM3 fs cat :error.log`.

## Если что-то не работает на первом запуске

- Нет звука при вставленной SD: в `config.py` поменять `DFPLAYER_SOURCE` на 1.
- Постоянно синее кольцо при вставленной SD: посмотреть `df.log`; если ваш клон не отвечает на запросы, поставить `SD_CHECK = False`.
- Один щелчок энкодера меняет громкость не на 1: подобрать `ENCODER_STEPS_PER_DETENT` (2 или 4).

## Установка MicroPython

На новую NodeMCU сначала один раз устанавливается стандартная прошивка `ESP8266_GENERIC` подходящей версии MicroPython. После этого проект работает как обычные `.py` файлы.

## Важное по boot-пинам

GPIO0 используется только кнопкой EC11 SW и является boot strap pin. Кнопка замыкает D3/GPIO0 на GND; второй контакт кнопки подключается к GND. На входе используется внутренний pull-up, поэтому **при включении/сбросе не нажимать EC11**. Канал B перенесён на D2/GPIO4.

GPIO2 используется DATA кольца WS2812 и должен оставаться HIGH во время запуска ESP8266. Не подключать DATA кольца к GND.

GPIO15 используется RC522 SS и должен оставаться LOW при старте; NodeMCU обеспечивает требуемое состояние для нормальной загрузки.

## Сброс привязок NFC

Файл `tagmap.json` хранит UID → папка. Если нужно начать нумерацию альбомов заново, удалить `tagmap.json` с файловой системы NodeMCU. После следующего запуска первый неизвестный тег снова получит `01`.
